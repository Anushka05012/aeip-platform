# Deploying AEIP

Two ways to run the whole platform: one machine with Docker, or the hosted setup
(Supabase + Render + Vercel). Every setting is optional except where marked **required**.

## Option A: one machine with Docker

```bash
cp .env.docker.example .env.docker   # optional: Groq/GitHub keys, login, roles
docker compose up --build
```

| URL | What |
|---|---|
| http://localhost:3000 | Dashboard |
| http://localhost:8001/health | Intelligence API |
| http://localhost:4000 | Ingestion service (GitHub webhooks, PostgreSQL) |

Compose runs PostgreSQL 16 with pgvector, applies the Prisma migrations, stores the vector index in
pgvector and bakes the local embedding model into the API image. Ports are bound to 127.0.0.1 only.
Data survives restarts in the `db-data` and `intelligence-cache` volumes (`docker compose down -v`
deletes them).

## Option B: hosted

### 1. Database: Supabase

1. Create a project. In **Database > Extensions**, enable **vector**.
2. **Project Settings > Database > Connection string**: copy the **Session pooler** URI (port 5432).
   This is `DATABASE_URL` for both backend services. The session pooler supports Prisma migrations
   and the API's prepared statements.

### 2. Backend: Render

1. **New > Blueprint**, choose this repository. Render reads [render.yaml](../render.yaml) and creates
   `aeip-intelligence` and `aeip-ingestion`.
2. Fill in the values it asks for:

| Variable | Service | Value |
|---|---|---|
| `DATABASE_URL` **required** | both | Supabase session pooler URI |
| `AEIP_SERVICE_TOKEN` **required** | intelligence | a long random string (`openssl rand -hex 32`); the same value goes to Vercel |
| `GROQ_API_KEY` | intelligence | https://console.groq.com/keys (without it answers are rule-based) |
| `GITHUB_TOKEN` | both | a read-only personal access token (full CI logs, higher rate limit) |
| `AEIP_ALLOWED_ORIGINS` | ingestion | the dashboard URL, e.g. `https://aeip.vercel.app` |

`AEIP_INGEST_KEY` and `GITHUB_WEBHOOK_SECRET` are generated by Render; copy them from the service's
Environment tab when you connect tools (step 4).

The API's embedding model needs about 1 GB of memory (the blueprint uses the Starter plan). On a
512 MB free instance set `AEIP_EMBEDDINGS=hashing`.

### 3. Dashboard: Vercel

1. **Add New > Project**, import this repository, set **Root Directory** to `frontend`.
2. Environment variables:

| Variable | Value |
|---|---|
| `INTELLIGENCE_API_URL` **required** | `https://aeip-intelligence.onrender.com` (your Render URL) |
| `AEIP_SERVICE_TOKEN` **required** | same value as on Render |
| `NEXT_PUBLIC_INGESTION_API_URL` | `https://aeip-ingestion.onrender.com` |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `AUTH_SECRET` | turn on sign-in (see below) |
| `AEIP_PUBLIC_URL` | the dashboard URL, e.g. `https://aeip.vercel.app` |
| `AEIP_ADMINS`, `AEIP_MEMBERS`, `AEIP_VIEWERS`, `AEIP_DEFAULT_ROLE` | who may sign in, with which role |

**Sign-in:** GitHub > Settings > Developer settings > OAuth Apps > New OAuth App. Homepage URL = the
dashboard URL; Authorization callback URL = `<dashboard URL>/api/auth/callback`. Generate
`AUTH_SECRET` with `openssl rand -hex 32`. Without these three values the dashboard runs open, which
is only acceptable on a private network.

### 4. Connect your tools

Each tool posts to the intelligence API with the ingest key (`AEIP_INGEST_KEY`):

| Tool | Where | URL |
|---|---|---|
| GitHub (commits, PRs) | repo Settings > Webhooks, secret = `GITHUB_WEBHOOK_SECRET` | `https://aeip-ingestion.onrender.com/webhooks/github` |
| Vercel deploys | Project Settings > Webhooks | `https://aeip-intelligence.onrender.com/api/events/vercel?repository=owner/name&key=<AEIP_INGEST_KEY>` |
| Render deploys | Service > Settings > Notifications > Webhook | `.../api/events/render?repository=owner/name&key=...` |
| Sentry errors | Settings > Integrations > Webhooks (internal integration) | `.../api/events/sentry?repository=owner/name&key=...` |
| GitHub deployments | repo webhook, event "Deployment statuses" | `.../api/events/github?repository=owner/name&key=...` |
| Prometheus Alertmanager | `webhook_configs`, `http_config.authorization.credentials: <key>` | `.../api/events/alertmanager?repository=owner/name` |
| Application or database logs | CI step, cron or log shipper | `python scripts/send_events.py --repository owner/name --logs app.log --source app` |


## Security checklist

- [ ] `AEIP_SERVICE_TOKEN` set on both Render and Vercel (the API rejects every caller without it).
- [ ] Sign-in configured and roles limited to your team.
- [ ] `AEIP_INGEST_KEY` set; tools use it.
- [ ] `GITHUB_TOKEN` is read-only. AEIP never writes to repositories, re-runs jobs or deploys.
- [ ] The audit log (`data/cache/audit.jsonl` on the API) is reviewed or shipped to your log store.
